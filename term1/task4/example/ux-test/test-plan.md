# UX 测试计划

> 示例计划。实际填写日期、Figma Prototype 起始节点 / 链接及版本、参与者代号和任务条件。观察记入 [原始观察](observations.md)，修改与复测见 [迭代记录](iterations.md)。

Figma 原型可验证流程、状态表达与文案理解；真实上传、自动保存、权限、键盘和读屏等需在可运行实现中另测。无实现时按 [交接记录](../handoff.md) 说明规则、待验证范围与反馈，不将模拟交互写为功能验证通过。

## 测试目标

- 验证核心任务"发布 → 联系 → 确认找回"闭环是否易发现、易理解、反馈及时
- 重点验证: 发布表单草稿自动保存、联系方式可见规则、状态流转提示

## 测试任务(接近真实场景, 不提前讲解操作方法)

| # | 任务 | 观察目标 |
| --- | --- | --- |
| 1 | 假设你在食堂丢了校园卡, 请发布一条失物信息 | 能否找到发布入口; 表单是否顺畅; 图片上传失败时的反应 |
| 2 | 你捡到一个水杯, 请发布一条招领信息 | 类型切换是否易理解 |
| 3 | 你怀疑某条信息是几天前的, 找到其状态 | 状态是否易发现、易理解 |
| 4 | 作为发布者, 有人联系你后请更新状态 | 状态流转入口是否可发现 |
| 5 | 新账号首次打开应用 | 空态是否清晰 |

## 环境

- 设备: 测试者自有手机(375px / 390px 宽度为主)
- 形式: Figma Prototype, 直接完成任务, 测试者不观看演示

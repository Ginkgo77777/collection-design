# Agent 与 Web 端 AI 对照（示例）

## 任务与统一验收标准

- 任务: 为博客新增可复用的文章 Callout，并同步深浅色 Token、移动端样式与示例文章。
- 范围: 只修改组件、Token、示例文章与对应测试，不改导航和构建配置。
- 验收: 构建通过；三种 Callout 状态可读；深浅色与窄屏无溢出；键盘 Focus 清晰；修改集中且可维护。

## 对照记录

| 维度 | Web 端 AI | 本地 Agent |
| --- | --- | --- |
| 上下文 | 人工粘贴组件与 Token 片段，遗漏了示例文章结构 | 读取 README、现有组件、Token、测试与 Git Diff |
| 产出 | 给出单文件代码片段，需人工拆分到项目 | 修改多个相关文件并运行构建与浏览器检查 |
| 错误恢复 | 根据人工转述的报错继续建议 | 观察实际报错，修复导入路径后重新验证 |
| 人工修正 | 4 处：命名、深色 Token、Focus、移动端换行 | 2 处：视觉间距和错误扩大的修改范围 |
| 主要风险 | 上下文缺失导致建议与既有约定冲突 | 写权限更大，可能同时改到无关文件 |

## 结论与人工决定

- 接受: Agent 对现有 Token 与测试结构的复用，因为 Git Diff 和真实构建能够验证。
- 修改: 将自动生成的散落间距改为既有 Spacing Token，并缩小文件范围。
- 拒绝: 为三个状态新增独立页面，原因是增加维护成本且不属于本次验收范围。
- 适用场景: Web 端适合先讨论目标与方案；本地 Agent 适合在明确权限内完成真实跨文件修改和验证。两者都不能替代最终视觉判断。

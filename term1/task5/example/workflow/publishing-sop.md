# 发布与维护 SOP(示例)

## 发布流程

1. 在 `content/posts/` 新建 Markdown，并补齐标题、摘要、日期、分类与图片说明。
2. 本地检查链接、代码块、长标题、横图、深浅色与移动端排版。
3. 压缩图片并确认来源与授权，运行构建和链接检查。
4. 提交 Git，等待自动部署，在公网地址复查文章。

## 验证记录

- 验证文章: `first-case-study.md`(示例)
- 发现并修复: 移动端代码块横向溢出；一张图片缺少说明文字。

实际填写新增或更新文章的线上链接、固定 Commit 的 Markdown 文件、操作日期、耗时、构建与发布结果；将回归结果链接到 [验证记录](validation.md)。上面是一篇维护验证的示例，不替代三篇真实文章的内容测试。

## 备份、迁移与交接

- Markdown、配置和自有图片随 Git 备份，部署凭据由平台管理。
- 每月检查失效链接；更换框架时优先迁移 Markdown 与静态资产。
- 接手者先阅读根 README、Token 配置和本 SOP，再运行项目自带的检查命令。

在 [提交 README](../README.md) 填写项目根 README 的固定版本链接，完整运行环境、启动 / 构建命令、部署配置、HTTPS、静态资源、回滚、迁移与交接说明在项目中维护；本页只记本次维护过程与必要摘要。

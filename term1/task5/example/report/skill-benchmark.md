# Skill 评测报告(示例)

## 评测设计

- 任务: 为个人博客设计一张"招新公告"横幅(边界明确: 尺寸 1200x630、需包含标题/时间/地点/二维码占位、明暗两版)
- Baseline: 不使用 Skill, 直接 Prompt 完成同一任务
- 候选: `canvas-design` 与 `ui-ux-pro-max`(目标、产物与工作方式具有可比性)
- 验收标准(预先写明):
  1. 信息层级正确(标题 > 时间地点 > 二维码)
  2. 网格与对齐清晰, 无散落数值
  3. 明暗两版一致性
  4. 生成物可编辑(HTML/SVG 源), 不依赖截图
  5. 极端内容(超长标题、超长英文)不破版

## 对照结果(示例)

| 维度 | Baseline(直接 Prompt) | canvas-design | ui-ux-pro-max |
| --- | --- | --- | --- |
| 鲁棒性 | 信息缺失时自行编造文案 | 会追问缺失信息 | 会追问, 但追问轮数多 |
| 泛用性 | 每次都要重新描述风格 | 提供可复用的画布约束 | 面向 UI 流程, 横幅任务适配一般 |
| 审美水平 | 不稳定, 2/5 次达标 | 构图稳定, 层级清晰 | 组件感强, 创意弱 |
| 风格化 | 口头风格词, 难以复现 | 拆解为网格/字体/色彩规则 | 依赖 UI Kit 风格 |
| 模块化 | 一次长 Prompt | 步骤清晰可替换 | 模块多, 调用链长 |
| 可维护性 | 不可复用 | SKILL.md 篇幅适中 | 文档长, 学习成本高 |
| 安全边界 | 无检查 | 未要求网络权限 | 未要求网络权限 |
| 通过验收 | 2/5 | 4/5 | 3/5 |

## 结论

- `canvas-design` 最适合本次海报式任务: 构图与层级稳定, 且能将风格拆为可执行规则
- `ui-ux-pro-max` 更适合界面流程类任务, 用于静态横幅时组件味过重
- 两者都无法替代人工判断: 均出现过"为了好看牺牲可读性"的结果, 需人工驳回
- 本次评测的完整 Prompt、输出与人工修改记录见个人仓库(示例占位)

## 成功与失败案例(示例)

- 成功: 使用 `canvas-design` 完成横幅明暗两版, 仅人工调整 1 处字距
- 失败: 要求某 Skill "生成赛博朋克风横幅", 结果直接模仿某在售游戏的美术风格与字体 → 存在版权风险, 已弃用并记录原因: 风格描述过于具体且未检查来源授权

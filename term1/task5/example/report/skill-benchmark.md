# Skill 评测报告(示例)

## 评测设计

- 任务: 为个人博客设计一张"招新公告"横幅(边界明确: 尺寸 1200x630、需包含标题/时间/地点/二维码占位、明暗两版)
- Baseline: 不使用 Skill, 直接 Prompt 完成同一任务
- 候选: `canvas-design`、`ui-ux-pro-max` 与基于本次真实问题自研的 `blog-layout-check` v2（目标、产物与验收方式保持可比）
- 验收标准(预先写明):
  1. 信息层级正确(标题 > 时间地点 > 二维码)
  2. 网格与对齐清晰, 无散落数值
  3. 明暗两版一致性
  4. 生成物可编辑(HTML/SVG 源), 不依赖截图
  5. 极端内容(超长标题、超长英文)不破版

## 对照结果(示例)

| 维度 | Baseline(直接 Prompt) | canvas-design | ui-ux-pro-max | blog-layout-check v2 |
| --- | --- | --- | --- | --- |
| 鲁棒性 | 信息缺失时自行编造文案 | 会追问缺失信息 | 会追问, 但追问轮数多 | 缺少尺寸或内容时停止并列出必填项 |
| 泛用性 | 每次都要重新描述风格 | 提供可复用的画布约束 | 面向 UI 流程, 横幅任务适配一般 | 可替换文章与尺寸，但不适合完整 UI 流程 |
| 审美水平 | 不稳定, 2/5 次达标 | 构图稳定, 层级清晰 | 组件感强, 创意弱 | 继承博客 Token，层级稳定但探索性有限 |
| 风格化 | 口头风格词, 难以复现 | 拆解为网格/字体/色彩规则 | 依赖 UI Kit 风格 | 只读取项目 Token，不内置固定视觉风格 |
| 模块化 | 一次长 Prompt | 步骤清晰可替换 | 模块多, 调用链长 | 输入、生成、检查与人工确认分离 |
| 可维护性 | 不可复用 | SKILL.md 篇幅适中 | 文档长, 学习成本高 | 规则较短，失败案例仍需继续补充 |
| 安全边界 | 无检查 | 未要求网络权限 | 未要求网络权限 | 只允许修改指定组件目录，外部资产需人工确认 |
| 通过验收 | 2/5 | 4/5 | 3/5 | 5/5 |

## 结论

- `canvas-design` 最适合本次海报式任务: 构图与层级稳定, 且能将风格拆为可执行规则
- `ui-ux-pro-max` 更适合界面流程类任务, 用于静态横幅时组件味过重
- `blog-layout-check` v2 最贴合现有博客 Token 与文件边界，但适用范围窄，不能据此宣称对其他设计任务同样有效
- 三者都无法替代人工判断: 均可能出现"为了好看牺牲可读性"或检查项未覆盖的问题, 需人工驳回
- 本次评测的完整 Prompt、输出与人工修改记录见个人仓库(示例占位)

## 成功与失败案例(示例)

- 成功: 使用 `canvas-design` 完成横幅明暗两版, 仅人工调整 1 处字距
- 失败: 要求某 Skill "生成赛博朋克风横幅", 结果直接模仿某在售游戏的美术风格与字体 → 存在版权风险, 已弃用并记录原因: 风格描述过于具体且未检查来源授权

## 新场景复测（示例）

- 新输入: 将招新公告替换为超长中英双语文章标题，并改为 4:5 社交平台尺寸。
- 原版问题: `canvas-design` 的默认字号在中文长标题下溢出，二维码安全区也未随尺寸调整。
- v2 修改: 增加真实内容预检、标题换行上限、二维码安全区与目标尺寸校验；缺少任一输入时停止生成。
- 结果: 原版 3/5 项通过，v2 5/5 项通过；人工仍调整了中文标点悬挂与标题节奏。

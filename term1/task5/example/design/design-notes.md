# 设计说明(示例)

## Purpose / Audience / Context

- Purpose: 用案例和文章展示设计判断，而不是只展示最终图片。
- Audience: 面试官需要快速找到代表作；学习者希望按主题阅读；维护者需要低成本更新。
- Context: 国内网络环境、移动端阅读、深浅色切换和长期维护成本。

## 基线与实施计划（实际填写）

- 同类博客与技术候选：填具体参考、借鉴 / 舍弃之处和最终选型理由。
- 内容范围、必要页面、技术限制与不做事项：实际填写，不必把所有分类 / 搜索功能都实现。
- 初始可运行版本：填源码 Commit、项目 README 与初次构建命令 / 结果，再据此推进后续修改。

## 视觉规则与取舍

- Grid: 桌面端 12 栏，正文限制最大行宽；移动端单栏。
- Typography: 标题、正文、注释和代码四级角色；文章页优先保证行长与行高。
- Color: 使用 Semantic Token 区分背景、文字、边框和强调色，深色模式单独校准。
- 修改记录: 按日期记录参考、发现的问题、修改内容、理由和验收结果；不要以“感觉更好”代替依据。
